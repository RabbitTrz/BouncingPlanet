一、只记三件事
----------------------------------------------------------------------
1. 开工先 Pull，收工要 Commit + Push。
2. 只改自己负责的文件/目录，不碰 Library、Temp、.meta。
3. 遇到冲突或红色报错先停手，截图问程序。
   不要 Force push、不要 Discard、不要删除 .git。

四个词：
  Clone  第一次把仓库下载到本地，只做一次。
  Pull   把别人的最新改动拉下来。
  Commit 在本地打一个存档点（此时别人还看不到）。
  Push   把存档点上传到 GitHub。


二、第一次使用（约 10 分钟）
----------------------------------------------------------------------
1. 安装：
   - GitHub Desktop：https://desktop.github.com/
   - Git LFS：https://git-lfs.com/
     安装后打开终端运行一次：git lfs install
   - Unity Hub + Unity 2022.3.62f3c1（不要升级）
2. 把你的 GitHub 用户名发给管理员，加入仓库 Write 权限，并接受邀请。
3. GitHub Desktop → File → Clone repository → 粘贴上面的仓库地址。
   本地路径建议：D:\GameJam\BouncingPlanet
   不要放在 OneDrive/网盘目录，不要用网页 Download ZIP。
4. Unity Hub → Add → 选择克隆下来的文件夹 → 用 2022.3.62f3c1 打开。
   第一次会生成 Library，等导入完成即可；Library 不需要提交。
5. 如果克隆后图片只有约 1KB 或打不开，是 Git LFS 没拉取：
   在仓库目录运行 git lfs install 和 git lfs pull。


三、目录与分工
----------------------------------------------------------------------
美术：
  Assets/Resources/Raw/      美术交付区：源文件、PSD/ASEPRITE/KRITA、导出的 PNG
                             都先提交到这里，按 角色/星球/UI/特效 建子目录。
  Assets/Resources/Image/    游戏实际引用的最终图；由程序确认后统一整理，
                             美术不要直接把未经确认的文件放这里。
音频：Assets/Resources/Audio/
策划：Assets/Config/（只改指定给你的资产）
程序：Assets/Scripts/、Assets/Scenes/、Assets/Prefabs/、
      ProjectSettings/、Packages/

规则：
  - 不新建顶层目录，不改目录结构。
  - 文件名用英文/拼音，不要中文、空格、特殊符号。
  - 新增/移动/重命名资源尽量在 Unity 里做；.meta 必须随资源一起提交。
  - 同一个场景/预制体同一时间只能一个人改；改完尽快提交并在群里说一声。
  - 不要改 ProjectSettings、Packages、.gitignore、.gitattributes（程序负责）。


四、每天的标准流程
----------------------------------------------------------------------
开工：
  1. 保存并关闭 Unity。
  2. 打开 GitHub Desktop，确认 Current Branch 是 main。
  3. 点击 Fetch origin，再 Pull origin。
  4. 重新打开 Unity，等待导入/编译完成。

收工：
  1. 保存，等 Unity 导入完成，然后关闭 Unity。
  2. 在 Changes 里检查：只应有自己的文件；新资源要有同名 .meta。
  3. 写提交说明，例如：[美术] 新增岩石星源文件
  4. 点击 Commit to main，再点击 Push origin。
  5. 如果 Push 被拒绝：先 Pull，再 Push；出现冲突就停手找程序。
  6. 在群里同步一句今天提交了什么。


五、提交说明格式
----------------------------------------------------------------------
格式：[角色] 一句话说明

  [美术]   图片、模型、动画资源
  [音频]   音乐、音效
  [策划]   数值、配置
  [程序]   代码、场景、预制体、工程设置
  [修复]   修 bug

一次提交只做一件事，不要写“update”“改了一下”。
示例：
  [美术] 新增果冻星源文件和导出图
  [策划] 调整冰星反弹系数
  [程序] 实现钩锁断开判定


六、绝对不要提交
----------------------------------------------------------------------
Library/、Temp/、Logs/、UserSettings/、Builds/、.vs/
*.csproj、*.sln、*.apk、*.aab、*.app、*.unitypackage

这些已经写在 .gitignore 里，正常不会出现。
如果出现在 Changes 里：不要勾选，截图告诉程序。

公开仓库注意：
  - 不要上传隐私、密码/Token、未获授权的付费素材或字体/音乐。
  - 提交记录会公开；管理员已使用 GitHub noreply 邮箱。
  - 第三方素材先确认许可证允许公开分发。


七、Git LFS（大文件）
----------------------------------------------------------------------
图片、PSD、音频、模型、视频、字体、插件已自动走 LFS。
不要修改 .gitattributes 里的规则。单个文件特别大（>100MB）先问程序。
如果克隆后拿到的是 LFS 指针文件：安装 Git LFS 后运行 git lfs pull。


八、常见问题
----------------------------------------------------------------------
Changes 里出现几千个 Library 文件
  → 不要提交，截图找程序。

Push 提示 rejected
  → 先 Pull origin，再 Push origin；冲突就停手。

Pull 提示有未提交改动
  → 不要点 Discard；先提交你的改动，或问程序。

不小心提交了大文件/密码
  → 立刻告诉程序，不要自己改历史或强推。

Unity 提示版本不一致/要升级
  → 取消升级，安装 2022.3.62f3c1。

资源丢失、材质变粉、脚本 Missing
  → 等 Unity 重新导入；检查 .meta 是否漏提交；仍不行截图问程序。

推送成功但别人看不到
  → 确认已 Push、分支是 main；让对方关闭 Unity 后 Pull。

不要用 GitHub 网页的 Upload files 上传 Unity 资源。
不要同时用两个 Unity 实例打开同一个工程。


九、管理员备忘
----------------------------------------------------------------------
  - 仓库保持空 main，加 Collaborator 时给 Write 权限。
  - 不建议强制 PR 流程；禁止 force push。
  - 关注 GitHub Settings → Billing 里的 LFS 配额。
  - 第三方素材在 CREDITS.txt 记录来源、作者、许可证。
  - 提交身份使用 GitHub noreply 邮箱，避免公开个人邮箱。
